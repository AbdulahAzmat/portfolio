Customer 360: E-Commerce Analytics

A full customer-segmentation and basket-analysis study built on the Olist Brazilian e-commerce dataset, covering roughly 100,000 orders across sellers, products, payments and reviews.

The problem

Retail customer data is awkward to cluster because it is genuinely mixed. Order counts and spend are numeric, while product category, payment type and state are categorical. Most clustering algorithms quietly assume one or the other, so the usual shortcut is to one-hot encode everything and hope Euclidean distance still means something. It rarely does.

What I did

Mined frequent itemsets and association rules with both Apriori and FP-Growth to find which product categories actually get bought together, then segmented customers using K-Prototypes and hierarchical clustering over Gower distance, which handles categorical and numeric features in the same distance space without forcing everything into one type.

Running two rule-mining algorithms against each other was deliberate: FP-Growth is far faster on this data, and agreement between the two is a reasonable check that the rules are real rather than artefacts of a support threshold.

FinSync: Banking Application

A desktop banking application built with a team, where I led the interface design and modelled the relational database behind it.

The problem

A banking app is mostly an exercise in not losing money. Two operations touching the same balance at the same time, or a transfer that debits one account and then fails before crediting the other, are the failure cases that matter, and they are invisible until they happen.

What I did

Designed the relational schema and enforced ACID compliance across every transactional path, so a transfer either completes in full or leaves no trace. That means wrapping the debit and credit in a single transaction rather than two statements that merely run next to each other.

On the interface side I built the flows for accounts, transfers and transaction history, aiming for screens that stay readable when an account has thousands of rows behind it rather than the dozen a demo usually shows.

Evidence-Based Hallucination Detection in LLMs

A retrieval-augmented verification framework for catching factual hallucinations in large language model output.

The problem

A language model produces fluent text whether or not it has grounds for it, and fluency is exactly what makes a hallucination hard to spot. Asking a model to rate its own confidence does not help much, because the same process that produced the claim produces the confidence score.

The approach

Rather than trusting the model's own certainty, the framework treats verification as a retrieval problem. Claims are extracted from the generated output and checked back against retrieved source evidence using semantic similarity, so a statement can be flagged specifically when nothing in the retrieved context actually supports it.

The distinction that matters is between a claim contradicted by the evidence and a claim merely absent from it. The second is far more common and much easier to miss.
